# Contributing

Thank you for helping improve our work. These guidelines are general defaults; repository-specific instructions take precedence.

## Before starting

1. Read the repository README, license and local contribution guidelines.
2. Search existing issues and pull requests to avoid duplicated work.
3. For substantial changes, open an issue to discuss the intended outcome before implementing it.

## Development workflow

1. Create a focused branch from the repository's default branch (`feature/short-description`, `fix/short-description`, or `docs/short-description`).
2. Keep each change scoped to one clear purpose.
3. Add or update tests and documentation when behavior changes.
4. Run the repository's relevant automated checks locally.
5. Open a pull request explaining the reason for the change, implementation approach, testing and any risks.
6. Request review where required; do not bypass repository protection rules.

## Quality standards

- Prefer readable, maintainable code over unnecessary complexity.
- Follow the conventions and formatting tools already in use.
- Consider accessibility, performance and localization for user-facing changes.
- Document breaking changes, data migrations and any operational impact.
- Never commit credentials, access tokens, private keys, private customer information or real production data.
- Avoid unrelated refactors in bug-fix pull requests.

## Collaboration

Be respectful and constructive. Follow [our Code of Conduct](CODE_OF_CONDUCT.md).

For security vulnerabilities, follow [SECURITY.md](SECURITY.md), **not** a public issue.
